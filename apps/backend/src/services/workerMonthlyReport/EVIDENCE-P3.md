## Implementation and integration

- Reports now uses `reportTab=barcode|production|worker-monthly`. Monthly filters are `wmMonth=YYYY-MM`, `wmProcess=coning`, `wmWorker=ID|all`. Existing unrelated search parameters are retained. Existing Barcode/Production implementations remain unchanged; the scanner view gains links to the other reports.
- Historical worker options come from the guarded workers endpoint. The full stable reference is visible beside each name, so duplicate names and previous process assignments remain distinct.
- Preview pagination displays 100 ledger rows globally, with clearly separate worker articles. Quality/day/month totals come directly from full-source aggregates. Each visible date ends with its full-date subtotal; when pagination shows only part of that date, the label identifies the shown/full row counts. A separate full daily summary includes work dates outside the current ledger page.
- A filter change invalidates results synchronously, aborts pending reads, and advances a request generation gate. Late preview/download/office responses cannot restore or save old selections. Browser Back and reload restore filters, but require a fresh preview.
- Downloads use authenticated fetch with the same filters, then save a Blob only if its request is still current. The server's `X-Report-Generated-At` is shown. The UI says exports are regenerated reads and tells staff to refresh the preview for comparison after a download. It does not claim immutable or shared cross-request snapshots.
- The office section labels selected eligible totals, all eligible totals, selected-month source accounting, exceptions, excluded stock, and unassigned-period records separately. Office references use independent chronological pagination and show their own generation timestamp. Changing ledger pages permits loading the corresponding office page; Excel contains the full selected-worker references.
- Every quality dimension is visible: item, side, yarn, trace-first cut, twist, cone type and target grams. Unknown row weight is `Unknown`; incomplete aggregate weight is an explicit known subtotal with unknown count. No source quantities are recomputed in the UI.
- Mobile filters wrap and ledger overflow is confined to its focusable container. A sideways-scroll hint explains how to reach machine/cones/kg. Desktop and mobile share identical source totals.

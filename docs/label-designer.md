# Label designer and label printing

Settings → Label designer. One design per stage (inbound, cutter issue, cutter issue small,
cutter receive, holo issue, holo receive, coning issue, coning receive, coning receive small).
Every stage flow prints the saved design through the same renderer that draws the preview.

## Using the designer

- **Stage** picker at the top left. The status next to it says *Saved*, *Unsaved changes*,
  *Factory default · not saved yet*, or *Converted from the old designer · review and save*.
- **Add** text, barcode, QR code, line, box or image from the left panel. The list below is the
  stacking order (top of the list prints on top). Hover a row to reorder, hide or lock it.
- **Canvas**: drag to move, handles to resize, shift-click or drag on empty space to select
  several. Arrow keys nudge 0.25 mm (Shift 1 mm). Delete removes. Ctrl/Cmd+D duplicates.
  Ctrl/Cmd+Z and Shift+Ctrl/Cmd+Z undo and redo. Hold Alt while dragging to skip snapping.
  Ctrl/Cmd + mouse wheel zooms.
- **Element** tab: position, size, rotation, and the type's own settings. Text has a font,
  size in real points, bold/italic/underline, alignment, and a rule for text that is too long:
  wrap then shrink, shrink only, wrap only, or clip. *Insert variable* puts an `@variable` at
  the caret; the variables are the stage's fields.
- **Label & roll** tab: label width (across the roll) and length (along the feed), design
  orientation (sideways designs are rotated onto the roll by the renderer), roll width, labels
  across, gaps, margins, calibration nudges and copies per transaction.
- **Sample data** (Typical, Long, Placeholders) fills the variables so the design is judged on
  real-looking values. Long values show how boxes wrap and shrink.
- **Print preview** shows the page exactly as the printer receives it, including columns and
  rotation, and sends a test label. On the desktop app the test prints silently; in a browser
  the system print dialog opens with the same page.
- **Reset** loads the factory design for the stage. Nothing changes on the server until **Save**.

Warnings appear on the element (amber badge), in the list, and in the inspector: text that does
not fit its box, a barcode wider than its limit, or an element outside the label.

## How it prints

1. The stage flow calls `printStageTemplatesBatch(stage, rows, options)` (unchanged API).
2. The saved template is laid out in millimetres with the real fonts: every text line gets an
   explicit position, barcodes become whole-dot rectangles, QR codes a module matrix.
3. The result is an artifact: HTML pages, a stylesheet and the bundled fonts as data URIs.
4. Desktop: the Electron print queue validates the artifact (no scripts, frames or external
   references), serves it to a hidden window through a private scheme and prints silently at
   100 % scale with the page size in microns. Browser: the same document goes to the operating
   system print dialog in a hidden frame.

The preview and the print share the page markup byte for byte; the designer only adds
selection handles and guides on top.

## Storage and compatibility

- Version 2 designs are stored in `StickerTemplate` under `v2:<stage>`. The previous
  designer's rows (`<stage>`) are left untouched and are converted on load when no version 2
  row exists yet; the status then reads *Converted from the old designer*. Press Save to keep
  the converted design or Reset for the factory design.
- Desktop builds up to 1.1.4 bundle the previous renderer and keep reading the legacy rows,
  so they print exactly what they printed before until the next desktop release.
- Factory designs are data: `apps/backend/scripts/stickerTemplates.v2.json`, generated by
  `node apps/frontend/scripts/export-label-defaults.mjs` from `utils/label/defaults.js` and
  seeded with `node apps/backend/scripts/seedStickerTemplates.mjs [--only-missing]`.
- The owner's production designs, refined for the new designer with the same fields and
  formation, are `apps/backend/scripts/stickerTemplates.production.json`, generated by
  `node apps/frontend/scripts/refine-production-labels.mjs` and seeded with
  `node apps/backend/scripts/seedStickerTemplates.mjs --file scripts/stickerTemplates.production.json`.
- Retained print jobs from older desktop builds (PNG artifacts) still reprint.

## Code map

- `apps/frontend/src/utils/label/`: `model.js` (template schema, limits), `migrate.js`
  (v1 → v2), `layout.js` (measuring, wrapping, shrinking, barcode and QR geometry),
  `html.js` (markup and page assembly), `artifact.js` (pages, columns, copies, limits),
  `barcode.js`, `placeholders.js`, `fonts.js`, `measure.js`, `defaults.js`, `sampleData.js`,
  `stages.js`.
- `apps/frontend/src/utils/labelPrint.js`: public API for stage flows and the designer.
- `apps/frontend/src/pages/Settings/LabelDesigner/`: the page.
- `apps/frontend/src/components/labels/LabelArtifactPreview.jsx`: exact-page preview.
- `apps/desktop/src/printing/`: validation, document assembly, hidden print window, queue.
- `apps/desktop/scripts/print-integration.cjs`: every stage through the production printer
  module in real Chromium (printToPDF + capture).
  It also prints two-label batches and asserts every page keeps the scale of a one-label job:
  Chromium measures a multi-page document's width from the unrotated positions of the text
  lines inside a sideways canvas, so the page box carries `contain: size` to stop it shrinking
  jobs whose text sits beyond the roll width.

## Verification

- `node --test apps/frontend/src/utils/__tests__/*.test.mjs`
- `node --test apps/desktop/test/*.test.cjs`
- `electron apps/desktop/scripts/visual-runner.cjs` (needs `npm run build:frontend` first)
- `electron apps/desktop/scripts/print-integration.cjs <output-dir>`
- Paper: print the test label from Workstation setup, measure its 2 mm margin, 50 mm line and
  20 mm square, and set that printer's Nudge X/Y in Workstation setup until they measure true.
  The nudge moves every label on that printer; a design's own Label & roll offsets are for the
  roll geometry, not for printer alignment. Then scan a barcode on every stage.

## Opacity and images

- Every element has an opacity of 100, 75, 50 or 25% (Inspector, Appearance). Thermal
  printers have no grey and their drivers turn anything lighter than black into blank paper,
  so a lighter element is drawn normally and covered by white vector hatch lines, two printer
  dots per step in every band of eight. The preview shows exactly that pattern. 25% suits a
  faint background logo; keep text at 50% or more and barcodes at 100%. The hatch also
  lightens anything underneath the element, so faint elements belong at the back. CSS masks
  and tiled backgrounds were tried and do not survive Chromium's print path on a sideways
  label; the hatch was verified on the TSC driver's actual printer bitmap.
- Images: PNG, JPEG, SVG, WebP or GIF up to 8 MB. Large or non-PNG/JPEG images are resized
  and re-encoded in the browser to fit the 150 KB stored limit (`utils/label/imageTools.js`).
  "Use company logo" takes the brand logo or favicon from Settings. "Make black and white"
  turns the image into pure black on transparent so it prints crisply; undo restores it.

## Variants

- Each stage can hold up to 20 named variants (picker next to the stage). Exactly one is
  **in use**: every new label of that stage prints it, in the web app and the desktop app.
- **New variant from this design** copies what is on screen (including unsaved edits) into a
  new variant and opens it; the variant in use does not change. **Save** stores the open
  variant. **Use for printing** stores it and makes it the one in use. Rename and Delete
  live in the ⋮ menu; the variant in use and the only variant cannot be deleted.
- Storage: `v2v:<stage>` holds `{ version: 1, activeId, variants: [{ id, name, template }] }`;
  the variant in use is also written to `v2:<stage>` in the same transaction
  (`PUT /api/sticker_templates/:stage/variants`), so every print path keeps reading one live
  design and older desktop builds are unaffected. A stage without a variants record shows its
  current design as the single variant "Standard".

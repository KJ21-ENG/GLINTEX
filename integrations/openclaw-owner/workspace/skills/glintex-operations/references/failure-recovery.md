# Failure recovery

- **Owner context rejected:** call no further GLINTEX tool. Explain that this
  deployment accepts only the verified owner's direct Telegram chat. Never
  weaken the owner ID, channel, or direct-message check.
- **Agent API not configured:** report that live GLINTEX access is unavailable.
  Do not request, paste, log, or expose the bearer token or confirmation secret.
- **Credential rejected:** report an integration credential problem, not a
  business-data result. Stop instead of seeking another credential or route.
- **Forbidden scope or resource:** name the unavailable capability and stop.
  Never probe for a broader route, session, shell, browser, or admin identity.
- **Validation error:** correct only an objective schema, enum, date, or limit
  mismatch. Ask one focused question if correction changes the business meaning.
- **Timeout or response-size limit:** narrow one process, date range, search,
  page, party, or company filter once. Do not retry in a loop.
- **Empty result:** restate exact filters and ask before broadening them.
- **Conflicting lineage, totals, or Tally evidence:** show the sources and compact
  arithmetic, label the missing evidence, and avoid a forced conclusion.
- **Duplicate:** present the exact existing task or candidate. Do not create a
  near-duplicate or silently change the title to bypass protection.
- **Stale update:** read the exact task again, explain the changed version, and
  prepare a new preview only if the owner's original intent remains unambiguous.
- **Expired or invalid confirmation:** do not execute. Prepare again only after
  re-reading current state and show the new preview and command.
- **Operation conflict:** read `operation_history` by exact ID. Never submit a
  second execution to race the first.
- **Execution failure:** report the durable failure code and do not claim the
  entity changed. Re-read both the operation and target before proposing a retry.
- **Verification failure:** report that execution cannot be confirmed. Do not
  claim completion or attempt an unrelated compensating action.
- **Unavailable mutation:** offer analysis or an owner task. Never imply that an
  inventory row, settlement, payment, message, deployment, file, memory, policy,
  model, or specialist changed.
